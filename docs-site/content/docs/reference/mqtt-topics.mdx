All device traffic is namespaced under `pullup/<DEVICE_ID>/…`, where `DEVICE_ID`
is the value shared between the [firmware config](/docs/firmware) and the
[web env](/docs/console/configuration).

## Published by the device

| Topic | Retained | What it carries |
|-------|:--------:|-----------------|
| `pullup/<DEVICE_ID>/telemetry` | no | Raw distance, continuously — drives the live gauge and calibration. |
| `pullup/<DEVICE_ID>/event` | no | `session_start`, `rep`, and `session_end` events. |
| `pullup/<DEVICE_ID>/env` | no | Temperature + humidity every 60 s (sampled only when idle). |
| `pullup/<DEVICE_ID>/status` | **yes** | Online flag, firmware version, WiFi RSSI, uptime, free heap, IP — every ~15 s. |
| `pullup/<DEVICE_ID>/ir/ack` | no | Ack for each IR frame sent. |
| `pullup/<DEVICE_ID>/ir/learned` | no | A remote frame decoded during learn mode: `{protocol, code, bits}`. |
| `pullup/<DEVICE_ID>/ota/status` | no | OTA download/flash progress. |

<Callout type="info" title="Offline detection">
The `status` topic is retained, and offline is delivered by the MQTT **Last-Will**
if the device drops — that's what flips the Device panel to offline.
</Callout>

## Subscribed by the device

| Topic | Retained | What it does |
|-------|:--------:|--------------|
| `pullup/<DEVICE_ID>/config` | **yes** | Detection thresholds + buzzer toggles. Changes from the **Settings** page arrive instantly — no reflashing. |
| `pullup/<DEVICE_ID>/ir/cmd` | no | An IR frame to transmit (see below). |
| `pullup/<DEVICE_ID>/ir/learn` | no | Toggle **learn** capture: `{ "on": true, "ms": 20000 }`. |
| `pullup/<DEVICE_ID>/ota` | no | An OTA image URL + MD5 to download and flash. |

## IR command payloads [#ir]

The device transmits whatever it receives on `ir/cmd`. Two shapes are supported:

**A Panasonic AC state frame** — a full climate state:

```json
{ "t": "climate", "power": true, "mode": "cool", "temp": 24, "fan": "auto", "swing": "auto" }
```

**A generic protocol code** — for buttons on any remote:

```json
{ "t": "button", "protocol": "NEC", "code": "00CF8976", "bits": 32 }
```

Commands are queued and transmitted right away in **any** state, so the fan/AC
responds instantly even while the bar sensor is active — an IR burst only pauses
distance sampling for a few tens of milliseconds. The device acks each send on
`ir/ack`.

<Callout type="info">
Devices and buttons are managed entirely on the web **Remote** page — nothing is
hard-coded in firmware. That's also what the
[voice integrations](/docs/integrations) ultimately drive.
</Callout>

## Learn mode [#learn]

With an [IR receiver](/docs/hardware/ir-blaster#receiver) on `GPIO14`, the console
can **capture** a code off your existing remote instead of you typing hex.

The server publishes `{ "on": true, "ms": 20000 }` on `ir/learn` to open a capture
window; the device enables its receiver and publishes each decoded frame on
`ir/learned`:

```json
{ "protocol": "NEC", "code": "20DF10EF", "bits": 32 }
```

The **Remote** page's "Learn from remote" button drives this and auto-fills the
new button's protocol / code / bits. The receiver's interrupt is only live during
the window (it auto-stops), so it never perturbs rep detection.

## OTA payload

`ota` carries the firmware image URL and its MD5. The device downloads over
HTTP(S), verifies the MD5, flashes the idle partition, and reboots — reporting
progress on `ota/status`. See [OTA updates](/docs/firmware/ota).
